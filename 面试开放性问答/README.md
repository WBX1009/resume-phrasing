**STAR 检查结果**

STAR 用于检查真实经历是否讲清情境（S）、个人任务（T）、关键行动（A）和结果（R）。口述稿按自然顺序组织，不要求说出这四个字母，也不要求每个结果都有数字。

| 位置 | 检查结论与本次调整 |
| --- | --- |
| 第一类 Q01：自我介绍 | 整题不套 STAR；项目摘要保留业务问题、个人职责、主要做法，并补明确已形成的报告能力。 |
| 第一类 Q03：实习介绍 | 原稿已具备 STAR。理顺“事实整理—疑点发现—补证核验”的行动顺序，分别说明系统交付和对照评测结果。 |
| 第一类 Q04：优势举例 | 原稿的学习方法较清楚，例子的任务和结果不够突出。补清核查需求、个人行动，以及报告与评测结果。 |
| 第一类 Q08：自评与协作 | 用现有竞赛资料组织“竞赛目标—个人参与的数据分析、建模与优化—团队获奖”，并保留分工与信息同步的协作习惯。现有资料不足以写出某次具体分歧协调或临时救场事件，因此不补造此类故事。 |
| 第二类 Q02-6：实习经验迁移 | 保留先回答经验价值的开头，再补清个人任务、行动和实际结果，最后说明可以迁移的经验与业务规则边界。 |
| 第二类 Q02-7：DeepAssist 与岗位的联系 | 补清项目目标，再讲知识库和智能体实现，最后用系统已经具备的能力作为结果，并说明与岗位的对应关系。 |

其余问题以观点、方法、匹配理由、偏好或计划为主，沿用直接回答的结构。其中：

- 第三类的压力应对、加班和团队期待属于个人态度与做法，不改写成未经提供的过去经历。
