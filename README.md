# 简历条目面试准备

围绕简历中的每条表达，先理解工作主线，再准备简洁、自然的口述回答与核心追问。目标是讲清自己的工作，不是逐字背诵完整知识库。

仓库：[WBX1009/resume-phrasing](https://github.com/WBX1009/resume-phrasing)

## 文件入口

| 文件 | 用途 |
| --- | --- |
| [简历.md](简历.md) | 简历正文，提供项目事实与条目范围 |
| [面试问答总集.md](面试问答总集.md) | 已打磨面试问答的统一入口，后续新问答在此补充和修改 |
| [简历条目面试讲解与问答生成规范.md](简历条目面试讲解与问答生成规范.md) | 两阶段流程、STAR、题型选择与回答标准的统一依据 |
| [任务提示词.md](任务提示词.md) | 每次选定条目后，复制对应阶段的短提示词 |
| [AGENTS.md](AGENTS.md) | 本地 AI 的任务路由 |
| [ChatGPT项目指令.md](ChatGPT项目指令.md) | 可粘贴到网页端项目中的指令，指向本仓库入口 |
| [项目源码/README.md](项目源码/README.md) | 两个项目的实现、测试与实习模型缓存的目录职责和读取路径 |

## 使用流程

1. 选定一条简历表达，用第一阶段提示词生成“本条理解”。检查问题、做法和结果之间的关系，必要时继续讨论。
2. 确认理解后，用第二阶段提示词生成本条口述讲解和必要的追问。两阶段分开进行。
3. 需要留存时，在指令中说明保存。一个条目的理解与问答放在同一份记录中，例如 `学习记录/DeepAssist/混合检索.md`；目录随实际内容建立。

跨会话继续时，提供已确认的“本条理解”正文或记录路径。简历中的案件研判属于实习项目，DeepAssist 对应个人项目“Agent 后端与知识库问答系统”。

网页端使用前，将 [ChatGPT项目指令.md](ChatGPT项目指令.md) 的正文放入项目指令，并确保 AI 能访问其中的文件。尚未同步远端时，可以直接提供相应 Markdown 文件。

规范负责方法和质量标准，AGENTS.md 负责读取路由，任务提示词只指定本轮阶段、条目和侧重，避免在多处重复维护完整规则。
