# 案件研判｜研判策略

## 简历条目

> **研判策略：**按业务口径**预设参数化 SQL**，筛选聚合百万级案件记录，形成结构化事实；结合风险识别规则与模型线索生成候选，以核验结果驱动**定向补证**；对照基线流程，最终风险事件：**精确率 81.0%→84.9%**，**召回率 85.0%→87.7%**。

> 本条理解状态：已确认（按用户要求保存本轮最终版本）。

## 第一阶段：本条理解

这条工作的核心是：先从案件记录中整理事实，再形成候选风险事件，通过补证和核验判断候选是否成立。它展示的是一套从数据处理到证据核对的研判方法。

1. **预设参数化 SQL：把业务口径落实为可复用的查询。**

   业务口径规定查哪些数据、怎样关联和统计；开发者据此预先编写 SQL，执行时传入人员、账户、时间范围等参数，由数据库完成筛选和聚合。

   “结构化事实”就是用明确字段表达查到的记录和统计结果，供后续分析与核对。“百万级”说明数据处理规模，不代表把百万条记录直接交给模型。预设查询便于保持口径一致，但新的查询需求可能需要补充或调整模板。

2. **规则与模型：根据事实形成候选，不能直接认定风险。**

   风险识别规则依据明确条件发现可疑情况，模型结合事实提出需要进一步检查的关联或线索，两者共同用于生成候选事件。

   这里要分清：查询事实回答“查到了什么”，候选事件回答“这些事实可能说明什么”。候选仍然需要证据支持，不能把规则触发或模型判断直接当成最终结论。业务查询口径与风险识别规则按用途区分；部分风险规则也可以用 SQL 实现，并非技术上完全分开。

3. **补证与核验：先查证候选，再根据缺口定向补查。**

   结合项目的完整流程，候选形成后开展补证，再集中核验；如果核验发现影响判断的证据缺口，就针对缺口进一步查询，补回的信息再用于核验。

   例如，仅用来说明机制：已经查到资金往来，但判断还缺少双方关系信息，就针对相关主体补查关系数据。“定向”的关键是，补查内容和范围由当前缺少的依据决定。补证既可能支持候选，也可能使其被修正或排除；证据仍不足，不等于候选已被证实。

4. **指标说明最终研判质量，不能单独证明某个环节的贡献。**

   这里评价的是补证、核验后的最终风险事件，不是候选阶段的召回率。

   精确率从 81.0% 提升到 84.9%，表示系统输出中符合标注标准的事件比例提高；召回率从 85.0% 提升到 87.7%，表示标注事件中被系统正确识别的比例提高。

   在统一的评测口径和可比条件下，这说明整套流程相较基线改善了最终识别质量。单项策略贡献多少，需要对应的消融结果，不能把整体提升全部归因于定向补证。

理解主线：按业务口径取数 → 从事实形成候选 → 补证后核验 → 根据缺口定向补查 → 用事件级评测验证整体效果。

## 第二阶段：面试问答

```text
Q01. 你是怎样设计这套研判策略的？

答：这部分要解决的是，从大量案件记录中发现疑点，并让最终判断有可核对的证据。

我先按业务口径预设参数化 SQL，筛选、聚合数据，形成结构化事实；再结合风险识别规则和模型线索生成候选。候选经过补证后集中核验，如果关键依据仍然不足，就针对缺口继续补查，再核验。

对照基线流程，最终风险事件的精确率从 81.0% 提升到 84.9%，召回率从 85.0% 提升到 87.7%。这是整套流程的对照结果。


Q02. 为什么采用预设参数化 SQL？具体怎样使用？

答：主要是为了固定查询和统计口径，让模型基于查到的事实分析。

我先根据业务需求写好 SQL，确定查询结构和统计方式；执行时传入人员、账户、时间范围等参数，由数据库完成筛选和聚合。查询结构预先确定，不让模型自由生成 SQL。

这样便于检查和复用查询逻辑。它的边界是查询能力受已有模板约束，遇到新的分析需求，需要补充或调整模板。


Q03. 风险识别规则和模型线索怎样配合？

答：规则按明确条件发现可疑情况，模型结合结构化事实提出值得进一步核查的关联或线索，两者共同用于形成候选事件。

这里的候选只是“值得查”，还不是“已经证实”。后续需要通过补证和核验，判断这些事实能否支持候选结论，不能仅凭规则触发或模型判断认定风险。


Q04. “以核验结果驱动定向补证”具体是什么意思？

答：就是把核验发现的证据缺口，转成有明确对象和范围的补查任务。

比如，为了说明机制：已有资金往来记录，但还缺少双方关系信息，就针对相关主体补查关系数据。查什么、查谁，以及查哪个时间范围，都应围绕当前缺口确定。

补回的信息再用于核验。它可能支持原候选，也可能推翻原来的判断；不能把补证理解成只寻找支持原结论的材料。


Q05. 这两个指标怎样评测？为什么能说明策略有效？

答：评价对象是最终输出的风险事件，以专家标注为参照。精确率看输出事件中有多少正确匹配标注，召回率看标注事件中有多少被正确识别。

我基于脱敏案件和专家标注构建事件级评测集，按案件划分开发集和测试集。在测试集上使用统一的事件匹配规则，并在相同候选上限和调用预算下比较基线与改进流程。

两项指标同时提高，说明在这组评测条件下，整体流程的误报占比和漏报比例都下降了。各项策略分别贡献多少，还需要结合对应的消融结果判断。
```
