# 模型专属调查工具详细设计

> 本文档是模型级 Investigation Agent 专属工具的施工级设计说明。
> Codex 应基于此文档设计并实现各模型的专属调查工具，使其产出结构化、可被 Judge 精确判断的证据。
>
> 阅读前提：已理解 `模型级Investigation-Agent详细设计.md` 中的 Agent 循环骨架，
> 以及 README 第 14.2 节 Baseline Strategy / Investigation Strategy 的双层策略。

## 一、当前工具的局限

当前 `src/supplement_tools.py` 提供 5 个通用工具：

| 工具 | 做什么 | 核心局限 |
|---|---|---|
| `entity_model_slice` | 对单个主体在单个模型内重新跑 `build_model_profiles` | 产出与 Baseline 几乎一致，无增量信息 |
| `relation_neighbor_subgraph` | 聚合一个主体在关系模型中的流入/流出边 | **最有用**，但只返回 count + amount，无结构分析 |
| `fund_flow_path_probe` | 从 source 出发探查两跳资金路径 | 仅限两跳，不分析路径模式 |
| `same_amount_window_probe` | 按日期+金额分组统计同日同额交易 | 仅做分组计数，不做模式分析 |
| `counterparty_overlap_probe` | 跨模型比较同一主体的对手方交集 | 只在 Baseline 的 counterparty_topk 上比较，不实际扫描数据 |

**共同问题**：
1. **summary 是自由文本**（"示例主体A在关系模型的邻域命中若干条记录"），Judge 难以做精确判断
2. **status_signal 太粗**：命中记录就 `enhanced`，无记录就 `weakened`，没有中间态
3. **不懂模型业务语义**：例如模型 86 的自转账、模型 43 的现金存取方向、模型 70 的对端户名分隔符
4. **没有多维交叉分析**：如"自转账占比 + 夜间占比 + 对手方 HHI"联合判断

## 二、工具设计原则

### 原则 1：一个工具回答一个明确的调查问题

```
不是：entity_model_slice(model_id=86, entity_name="示例主体A") → "命中若干条"
而是：transfer_structure_analyzer(entity_name="示例主体A")
      → 回答："示例主体A的转账行为是否呈现集中控制特征？"
      → 证据：自转账占比76%、对手方HHI=3200（高度集中）、夜间占比48%、
        基金/现金循环模式3组
```

### 原则 2：工具的输入来自 Baseline，输出供 Judge 消费

```
BaselinePack.entity_ranking
  → 告诉你"谁值得调查"（示例主体A排第1，N条记录，M个对手方）
  → Agent Planner 选择"先调查示例主体A"
  → 调用 transfer_structure_analyzer(entity_name="示例主体A")
  → 产出结构化证据包
  → Judge 基于结构化字段做判断：
    "自转账占比76%>阈值50% AND 夜间占比48%>阈值30% AND HHI>2500
     → 增强该假设"
```

### 原则 3：一个模型可以有多个工具，各司其职

- **结构分析工具**：回答"整体模式是什么"（如自转账占比、对手方集中度）
- **聚焦分析工具**：回答"某个特定对手方/时间段/账户的细节是什么"
- **比较分析工具**：回答"这个主体与其他 Top 主体有什么异同"

### 原则 4：工具产出结构化 schema，不只 summary 文本

```python
# 不好的产出（当前通用工具）
{"summary": "示例主体A在关系模型的邻域命中若干条记录。", "status_signal": "enhanced"}

# 好的产出（专属工具）
{
  "summary": "示例主体A共若干条转账记录。自转账占比X%（示例）；夜间占比Y%；HHI=N；检测到N组资金循环。",
  "structured": {
    "self_transfer_ratio": 0.76,
    "night_ratio": 0.48,
    "counterparty_hhi": 3200,
    "fund_cycle_count": 3,
    "account_count": 15,
    "anomaly_flags": ["self_transfer_dominant", "night_intensive", "high_concentration", "fund_cycle_detected"]
  },
  "status_signal": "enhanced",
  "evidence_records": [...]  # 代表性原始记录
}
```

### 原则 5：工具有硬边界

- 只扫描本模型的数据（`model_id` 硬编码，不接受参数）
- 不超过预算（`max_rows_per_call`, `max_unique_groups`）
- 不生成 SQL
- 不跨模型访问
- `truncated=true` 时 `status_signal` 强制为 `unresolved`（与当前 `_finalize_tool_result` 一致）

## 三、工具分类体系

```
工具类型
├── 通用工具（对所有模型可用）
│   ├── entity_model_slice          # 主体定向切片（已实现）
│   ├── relation_neighbor_subgraph  # 关系邻域（已实现）
│   ├── fund_flow_path_probe       # 资金两跳路径（已实现）
│   ├── same_amount_window_probe   # 同日同额窗口（已实现）
│   └── counterparty_overlap_probe # 对手方重合（已实现，仅用 Baseline）
│
└── 专属工具（绑定到特定模型）
    ├── 模型86专属
    │   ├── transfer_structure_analyzer      # 转账结构深度分析
    │   ├── counterparty_identity_profiler   # 对手方身份画像
    │   └── transfer_timeline_analyzer       # 转账时间线分析
    │
    ├── 模型43专属
    │   ├── cash_flow_direction_analyzer     # 现金存取方向与模式分析
    │   └── cash_account_correlator         # 多卡关联分析
    │
    ├── 模型70专属
    │   ├── same_amount_pattern_detector    # 同日同额转账模式检测
    │   └── counterparty_list_analyzer      # 对端户名清单分析
    │
    ├── 模型101专属
    │   ├── scattered_outflow_analyzer      # 整进散出结构分析
    │   └── fund_承接_chain_analyzer        # 资金承接链分析
    │
    └── 模型5专属
        ├── balance_distribution_analyzer   # 余额分布与异常分析
        └── account_timeline_correlator    # 账户时间线关联分析
```

## 四、各模型专属工具详细规格

### 4.1 模型 86：银行转账关系分析（L2, relation, 420,476 条）

**模型数据特征**：
- 字段：流出对象（起点）、流入对象（终点）、流出账户、流入账户、交易金额、交易时间
- 每条记录 = 一笔转账的起点→终点边
- 规模最大，关系最密集

**核心调查问题**：
1. 该主体的转账网络结构是否呈现集中控制特征？
2. 对手方的身份分布和资金承接关系如何？
3. 转账行为在时间维度是否有异常模式？

#### 工具 86-A：`transfer_structure_analyzer`

```
调查问题：该主体的转账行为是否呈现集中控制或分层转移的结构特征？

输入参数：
  entity_name: str          # 必填，主体名称
  min_amount: float | None  # 可选，最低金额过滤（默认不过滤）

产出结构化字段：
  # 规模指标
  total_rows: int                    # 命中总记录数（含自转+对外）
  total_amount: float                # 金额合计（元）

  # 自转账指标（关键异常信号）
  self_transfer_count: int           # 自转账笔数
  self_transfer_amount: float        # 自转账金额
  self_transfer_ratio: float         # 自转账笔数占比（0-1）
  self_transfer_amount_ratio: float  # 自转账金额占比（0-1）

  # 对手方集中度
  distinct_counterparty_count: int   # 去重对手方数
  counterparty_hhi: float            # HHI 指数（0-10000，>2500 为高度集中）
  top_outgoing: list[dict]           # 主要流出对手方 Top5（不含自转）
    - target: str                    #   对手方名称
    - amount: float                  #   金额合计
    - count: int                     #   笔数
    - amount_ratio: float            #   占该主体总流出金额的比例
  top_incoming: list[dict]           # 主要流入对手方 Top5（不含自转）

  # 时间模式
  night_ratio: float                 # 夜间交易占比（22:00-06:00）
  hour_concentration: float          # 小时集中度（Top3 小时占比）
  day_concentration: float           # 日集中度（金额最大的一天占总金额比例）
  weekend_ratio: float               # 周末交易占比
  time_span_days: int                # 时间跨度（天）
  active_years: int                  # 活跃年数

  # 账户结构
  distinct_account_count: int        # 涉及的独立账户数
  account_pairs: list[dict]          # 主要账户对 Top5
    - source_account: str            #   流出账户（脱敏后）
    - target_account: str            #   流入账户（脱敏后）
    - count: int                     #   笔数
    - amount: float                  #   金额

  # 资金循环检测
  fund_cycle_patterns: list[dict]    # 检测到的资金循环
    - pattern_type: str              #   类型：self_loop | a_b_a | triangle | chain
    - entities: list[str]            #   涉及主体
    - total_flow: float              #   循环总金额
    - round_trips: int               #   往返次数

  # 异常标记（供 Judge 直接消费）
  anomaly_flags: list[str]           # 触发的异常标记
    # 可选值：self_transfer_dominant | high_concentration |
    #        night_intensive | weekend_active |
    #        multi_account_rotation | fund_cycle_detected |
    #        rapid_growth | amount_jump_pattern

  # 证据
  evidence_records: list[dict]       # 代表性原始记录（最多5条）

status_signal 判断规则（确定性）：
  IF anomaly_flags 包含 >= 2 个标记 → "enhanced"
  ELSE IF total_rows > 100 AND anomaly_flags 包含 >= 1 个标记 → "enhanced"
  ELSE IF total_rows == 0 → "weakened"
  ELSE → "unresolved"
```

**异常标记的触发规则（确定性阈值）**：

```python
def _detect_transfer_anomalies(structured: dict) -> list[str]:
    flags = []

    # 自转账占比异常
    if structured["self_transfer_ratio"] > 0.5:
        flags.append("self_transfer_dominant")
    elif structured["self_transfer_amount_ratio"] > 0.7:
        flags.append("self_transfer_dominant")

    # 对手方高度集中
    if structured["counterparty_hhi"] > 2500:
        flags.append("high_concentration")

    # 夜间交易密集
    if structured["night_ratio"] > 0.3 and structured["total_rows"] > 100:
        flags.append("night_intensive")

    # 周末活跃
    if structured["weekend_ratio"] > 0.25:
        flags.append("weekend_active")

    # 多账户轮转
    if structured["distinct_account_count"] >= 5 and structured["total_rows"] > 500:
        flags.append("multi_account_rotation")

    # 资金循环
    if structured["fund_cycle_patterns"]:
        flags.append("fund_cycle_detected")

    # 金额跳跃（中位数 vs 平均值差异巨大）
    # 此信息来自 Baseline，不在此处计算

    return flags
```

#### 工具 86-B：`counterparty_identity_profiler`

```
调查问题：该主体的对手方中，哪些是个人/企业/金融机构？是否存在资金归集到少数机构的现象？

输入参数：
  entity_name: str          # 必填

产出结构化字段：
  counterparty_categories: dict
    # 对手方分类（基于名称规则匹配）
    personal: list[dict]       # 个人对手方
    corporate: list[dict]      # 企业对手方
    financial: list[dict]      # 金融机构/基金对手方
    government: list[dict]     # 政府/事业单位
    self: dict                 # 自身交易
    # 每组包含：{name, count, amount, amount_ratio}

  category_concentration: dict
    # 各类别金额占比
    personal_ratio: float
    corporate_ratio: float
    financial_ratio: float
    self_ratio: float

  top_intermediate_nodes: list[dict]
    # 识别可能的"中转节点"（同时出现在流入和流出 Top10 中的对手方）
    - name: str
    - incoming_amount: float
    - outgoing_amount: float
    - net_flow: float             # 净流入（流入-流出），正=资金沉淀，负=资金流出
    - is_suspicious_中转: bool    # 流入≈流出（差额<10%）→ 可能是过桥账户

  anomaly_flags: list[str]
    # 可选值：financial_counterparty_concentration |
    #        self_dealing_dominant | suspected_bridge_accounts

status_signal:
  IF suspected_bridge_accounts 非空 → "enhanced"
  ELSE IF financial_counterparty_concentration → "enhanced"
  ELSE → "unresolved"
```

#### 工具 86-C：`transfer_timeline_analyzer`

```
调查问题：该主体的转账行为在时间维度是否有异常模式？
         是否有明显的活跃期/休眠期交替？是否存在金额随时间增长的趋势？

输入参数：
  entity_name: str          # 必填
  granularity: str          # 可选，时间粒度："month" | "day" | "hour"，默认 "month"

产出结构化字段：
  monthly_timeline: list[dict]     # 按月聚合的时序数据
    - year_month: str               #   如 "2024-03"
    - count: int                    #   笔数
    - amount: float                 #   金额
    - unique_counterparties: int    #   对手方数

  quarterly_aggregates: list[dict]  # 按季度聚合
    - year_quarter: str
    - count: int
    - amount: float
    - avg_amount: float
    - counterparty_count: int

  trend_indicators: dict
    growth_rate: float              # 最近4季度 vs 前4季度的金额增长率
    volatility: float               # 月度金额的标准差/均值
    active_quarters: int            # 有交易的季度数
    dormant_quarters: int           # 无交易的季度数
    max_single_month_ratio: float   # 单月最大金额/总金额

  anomaly_flags: list[str]
    # 可选值：rapid_growth | sudden_surge | seasonal_pattern |
    #        dormant_then_active | stable_high_frequency

status_signal:
  IF rapid_growth OR sudden_surge → "enhanced"
  ELSE IF volatile AND active_quarters > 8 → "unresolved"
  ELSE → "unresolved"
```

### 4.2 模型 43：大额存取现（L1, entity, 2,964 条）

**模型数据特征**：
- 字段：姓名、卡号、对手账户、交易对手、金额、交易时间、方向、余额、摘要、身份证
- 每条记录 = 一笔大额现金存入或支取
- 方向字段区分流入/流出
- 摘要包含产品信息（如理财申购/赎回）

**核心调查问题**：
1. 该主体的现金存取行为模式是什么？流入 vs 流出比例？是否存在"存后即取"的短周期模式？
2. 多张银行卡之间是否存在关联操作（同一时段多卡同时操作）？
3. 现金存取是否与理财产品申购/赎回关联？

#### 工具 43-A：`cash_flow_direction_analyzer`

```
调查问题：该主体的现金存取在方向、金额、时段上是否有值得关注的集中特征？

输入参数：
  entity_name: str          # 必填

产出结构化字段：
  # 方向分布
  direction_distribution: dict
    inflow_count: int               # 流入（存入）笔数
    outflow_count: int              # 流出（支取）笔数
    inflow_amount: float            # 流入金额
    outflow_amount: float           # 流出金额
    net_flow: float                 # 净流入（流入-流出）
    inflow_outflow_ratio: float     # 流入/流出笔数比

  # 金额分布
  amount_distribution: dict
    bins: dict                      # 金额区间分布（<5万/5-10万/10-50万/50-100万/>100万）
    near_threshold_count: int       # 临界金额笔数（4.5万-5万区间）
    near_threshold_amount: float    # 临界金额合计
    round_number_ratio: float       # 整数金额笔数占比（可能是柜台取整）

  # 时间集中度
  hour_concentration: dict
    top_hours: list[dict]           # 最高频时段 Top3
      - hour: int
      - count: int
      - amount: float
    business_hour_ratio: float      # 营业时间占比（09:00-17:00）
    after_hour_ratio: float         # 非营业时间占比

  # 对手方模式
  counterparty_patterns: dict
    unique_counterparties: int      # 去重对手方数
    cash_counterparty_ratio: float  # 对手方为"现金"的占比
    top_counterparties: list[dict]  # 主要对手方 Top5

  # 摘要分析（关键）
  summary_patterns: dict
    wealth_management_related: int  # 涉及理财/结构性存款的笔数
    wealth_management_amount: float # 涉及理财的金额
    has_multiple_products: bool     # 是否涉及多个理财产品

  anomaly_flags: list[str]
    # 可选值：inflow_outflow_imbalance | near_threshold_concentration |
    #        after_hour_activity | wealth_product_cycling |
    #        multi_card_concurrent | round_amount_preference

status_signal:
  IF anomaly_flags >= 2 → "enhanced"
  ELSE IF total_rows > 100 AND anomaly_flags >= 1 → "enhanced"
  ELSE → "unresolved"
```

```
输入参数：

产出结构化字段：
```

### 4.3 模型 70：相近时间多笔相同金额转账（L1, entity, 8,618 条）

**模型数据特征**：
- 字段：本方户名、本方银行卡号、对端户名清单、转出金额、交易日期、对端银行卡号清单、同日相同金额转不同对端数量
- 关键特征：对端户名清单是用分隔符（`|`或`、`）连接的多个对手方名称
- 同日相同金额转不同对端数量 ≥ 2（这是该模型的筛选条件）

**核心调查问题**：
1. 该主体的同日同额转账呈现什么模式？金额分布、对手方分布、时间聚集度如何？
2. 是否存在"拆分转账"嫌疑（同日多笔同额小金额转给不同人）？
3. 对手方之间是否有关联关系（如同一公司、同一地域）？

#### 工具 70-A：`same_amount_pattern_detector`

```
调查问题：该主体的同日同额转账模式是否呈现拆分转账的结构化特征？

输入参数：
  entity_name: str          # 必填

产出结构化字段：
  # 规模与集中度
  total_groups: int                  # 同日同额组合总数
  total_amount: float                # 金额合计
  total_counterparties: int          # 涉及的去重对手方数（从对端户名清单中解析）

  # 金额模式
  amount_distribution: dict
    typical_amounts: list[dict]      # 出现频次最高的金额 Top5
      - amount: float
      - group_count: int             #   出现次数（同日同额组数）
      - avg_counterparties_per_group: float  # 每组平均对手方数
    max_counterparties_in_one_group: int     # 单组最多对手方数
    amount_diversity: float          # 金额多样性（不同金额数/总组数，低=金额固定）

  # 对手方模式
  counterparty_frequency: list[dict] # 最常出现的对手方 Top10（跨不同金额组合）
    - name: str
    - appearance_count: int          #   出现次数
    - total_amount: float            #   涉及金额
  counterparty_co_occurrence: list[dict]  # 经常一同出现的对手方组合
    - pair: list[str]
    - co_occurrence_count: int

  # 时间模式
  date_distribution: list[dict]      # 按日期聚合
    - date: str
    - group_count: int               #   同日同额组数
    - amount_sum: float

    #        daily_intensive | suspected_split_transfer |
```

```python
{
    # ── 必填字段 ──
    "summary": str,
    # 一句话中文摘要，包含关键数字和主要发现。
```

## 六、工具注册与发现机制

### 6.1 注册方式

```python
# src/model_tools/registry.py

from dataclasses import dataclass
from typing import Any, Callable

@dataclass(frozen=True)
class ToolRegistration:
    name: str                           # 工具名（全局唯一）
    description: str                    # 中文描述（供 Planner 参考）
    required_params: tuple[str, ...]    # 必需参数
    optional_params: tuple[str, ...]    # 可选参数
    model_ids: tuple[int, ...]          # 绑定的模型 ID（空=通用工具）
    model_kinds: tuple[str, ...]        # 适用的模型类型
    func: Callable                      # 工具函数
    is_specialized: bool = True         # 是否为专属工具

# 专属工具注册表
MODEL_SPECIFIC_TOOLS: dict[str, ToolRegistration] = {}

def register_tool(reg: ToolRegistration) -> None:
    """注册一个专属工具"""
    if reg.name in MODEL_SPECIFIC_TOOLS:
        raise ValueError(f"工具 {reg.name} 已注册")
    MODEL_SPECIFIC_TOOLS[reg.name] = reg

def get_tools_for_model(model_id: int, model_kind: str) -> list[ToolRegistration]:
    """获取某模型可用的所有工具（通用 + 专属）"""
    tools = []

    # 通用工具
    for name, spec in TOOL_REGISTRY.items():
        if not spec.model_kinds or model_kind in spec.model_kinds:
            tools.append(ToolRegistration(
                name=name,
                description=spec.description,
                required_params=spec.required_params,
                optional_params=spec.optional_params,
                model_ids=(),
                model_kinds=spec.model_kinds,
                func=None,  # 通用工具通过 execute_tool 调用
                is_specialized=False,
            ))

    # 专属工具
    for name, reg in MODEL_SPECIFIC_TOOLS.items():
        if model_id in reg.model_ids:
            tools.append(reg)

    return tools
```

## 九、与通用工具的关系

专属工具**不替代**通用工具。它们的关系是：

```
Agent Planner 的决策顺序：
  1. 优先选择专属工具（因为产出更精细，更适合做判断）
  2. 如果专属工具已全部调用过，选择通用工具作为补充
  3. 如果连通用工具都已调用过，输出 stop
  4. 如果模型没有专属工具（如 L0 模型），仅使用通用工具

工具产出的使用：
  通用工具产出 → summary 文本 → Judge 基于文本理解判断（当前方式）
  专属工具产出 → structured + anomaly_flags → Judge 基于规则+文本判断（目标方式）
  专属工具产出也可以被后续的通用工具引用（如 transfer_structure_analyzer
    发现自转账占比高 → 触发 fund_flow_path_probe 追踪外部资金去向）
```
